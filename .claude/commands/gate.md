---
description: Run full checks, then the independent critic. Fix on REJECT, stop on ACCEPT (leads to Gate 2)
argument-hint: [task-dir-name, default is the one in tasks/.active]
---

Run the verification gate for task: $ARGUMENTS (if empty, use the directory named in `tasks/.active`).

Let `T` be that task directory under `tasks/`. Read `T/contract.md` first. If its status is not `APPROVED` or `T/APPROVED` does not exist, stop and say so: the human approves with `./scripts/approve.sh`.

1. **Checks.** Run `./scripts/check.sh --full`. It appends a run section to `T/checks.log` (the current run is the last `# check run` section). If a step FAILS, this is not ready for the critic: classify the failure (tool problem, bad arguments, missing context, failing behavior, contradictory requirement), fix the cause, and re-run. Respect `budgets` in `harness.yml`: a retry must change something relevant; the same failure twice in a row means stop and escalate to the human with the evidence.
2. **Evidence pass.** Be the first reviewer of your own proofs, before the critic. Go through EVERY acceptance item of `T/contract.md`, one by one, and find the proof the contract names for it: the test name in the last run section of `T/checks.log`, a `# red run` section, the raw output of a named command, a measure or a manual result in `T/state.md`. Start with `./scripts/evidence.sh T`: for every acceptance item it lists the tests the contract names in backticks and where each passed in `T/checks.log`, on the current build (the same `work=` as the last run) or only on an older one. Its PROBLEM lines count as MISSING below; its BY HAND items you match yourself, as described here. Then use Grep on the logs, not memory. Write the result into `T/state.md` under PROGRESS as a list headed `evidence pass <N>` (N is the critic round): item, kind of proof (`test`: a named test that passed; `trace`: raw command output in the log; `manual`: the human's words; `claim`: only the author's own text), where the proof is (file:line), or MISSING (a `claim` is MISSING). A proof that exists in another form than the contract names (a manual item instead of a named test, fewer cases, a weaker assertion) is MISSING, unless `## CONTRACT CHANGES` in `T/state.md` has an entry for it with the human's words. Then: a MISSING proof that is only a command to run and log, run now and log the way the contract says; a MISSING test that fits the contract's scope, write and go back to step 1; anything else (the proof cannot be done as written, or you want to move or weaken it) is a contract change: write the item, the contract's text and your proposal under `## CONTRACT CHANGES`, stop and ask the human. Do not start the critic while any item is MISSING. If `/work` already wrote an evidence pass for this same change, re-check only what changed since.
3. **Manual acceptance, only if the contract has manual items.** Prepare it before you ask the human to test, not after. Write `T/acceptance-cases.md`: for every manual item, numbered cases (M1.1, M1.2, ...), each case one action and the one thing to observe, with an empty answer line; at the top, how he can tell he runs this build. Give him the file and ask for an answer per case: yes / no / not checked, and what he saw when it is not yes. A blanket answer ("all works") closes nothing: ask again about the cases without their own answer. Copy his words into `## MANUAL ACCEPTANCE` in `T/state.md` (add the section if the task has none). "not checked" is not a pass: either he checks it, or it becomes a `## CONTRACT CHANGES` entry that moves the case to NOT VERIFIED in his words. After any code change that follows his pass, tell him which cases to repeat and ask.
4. **Evidence package.** Save the change to `T/diff.patch`: the output of `git diff HEAD`, followed by a line `--- untracked files ---` and the output of `git ls-files --others --exclude-standard`. Then save the same content to `T/diff.attempt-<N>.patch`, where N is the number of this critic round for the task (1 for the first round): `diff.patch` is overwritten by the next round, the numbered copy shows later which change a verdict was about. Never edit or delete a numbered copy. If the project is not a git repository, instead list every file you changed, with paths, in `T/diff.patch`.
5. **Critic.** Before launching it, if `T/state.md` has a `## MANUAL ACCEPTANCE` section, `grep` its fields and stop on an empty value or a template placeholder (ask the human). Launch the critic in a separate step from any edit of `state.md`, never in the same response. Then launch the `critic` subagent (Agent tool, subagent_type `critic`). Give it only paths, not your opinion: `T/contract.md`, `T/checks.log`, `T/diff.patch`, `T/state.md`. Do not argue its case for it.
6. Save the critic's answer **verbatim** to `T/verdict.md`, and the same text to `T/verdict.attempt-<N>.md` (N as in step 4; never edit a numbered copy).
7. **If `REJECT`:** record the attempt in `T/state.md` under ATTEMPTS, in the format of that section (EXPECTED, SAW, FENCE, DEAD ENDS), and the blockers under PROGRESS and LESSONS. Before you fix anything, read ATTEMPTS and the earlier `T/verdict.attempt-<N>.md` files: a listed dead end is not tried again. If a blocker comes back (the same acceptance item, the same missing proof or the same defect as in an earlier round) `budgets.max_unchanged_failures` times in a row, the fixes are not learning from the verdict: stop now, write the blocker, what was tried and what the critic keeps asking for under PROGRESS/blocked, and ask the human. The missing piece is usually something you cannot see, or a contract that is framed wrong. Otherwise fix exactly what the findings name, then go back to step 1. After `budgets.max_repair_attempts` rejections, stop: write the open findings under PROGRESS/blocked, and ask the human how to proceed. Run `/retro` if the failure looks preventable by the harness.
8. **If `ACCEPT`:** run `/receipt`. Then stop. Gate 2 belongs to the human.

Never edit `verdict.md` after the critic wrote it. Never mark the task done yourself.
